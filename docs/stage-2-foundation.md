## Что проверяем

Одна команда изменяет данные, сохраняет историю, результат обработки Telegram update и задание ответа одной транзакцией. Повтор события возвращает сохранённый результат; одновременные повторы проходят через блокировку единственной строки барбершопа. Время берётся из PostgreSQL после получения блокировки. Ожидаемый отказ откатывает изменения команды до savepoint, непредвиденный сбой откатывает всю транзакцию.

Пока только /start. После commit отдельный ожидаемый адаптер отправляет сохранённый ответ и отмечает доставку. Ошибка отправки или отметки возвращает webhook 5xx; повтор восстанавливает доставку, сохраняя один эффект команды. При неопределённом результате отправки Telegram сообщение может повториться. Два одновременных повтора webhook также могут прочитать pending-сообщение до отметки отправки и оба отправить его; бизнес-эффект остаётся один. Leases и полная защита доставки от конкуренции относятся к этапу 4. Это промежуточная доставка через повторы webhook, а не полный фоновый планировщик этапа 4. Действующий ProbeScheduler и его миграция не удаляются.

## Миграции и восстановление

Миграции нумеруются, проверяют checksum и сериализуются advisory lock; SQL и запись применённой миграции фиксируются транзакцией. Повтор не меняет схему, изменение уже применённого файла запрещено. Seed идемпотентный, только вымышленные данные, без Telegram.

Для этой ветки восстановления существующих клиентов не требуется: в родительской базе этапа1 бизнес-таблиц ещё нет, новая схема проверяется отдельно. Автоматического DROP/down нет. При неудачной миграции PostgreSQL откатывает её транзакцию. После commit исправления делаются новой миграцией; откат кода не отменяет схему и данные. Перед будущим применением к базе бота нужны отдельная проверка совместимости и точка восстановления. Тестовую ветку автоматически не удаляем.

## Приёмка

- Повтор и одновременный повтор update дают один эффект.
- Сбой после истории/outbox не оставляет частичных данных.
- Сбой после commit перед доставкой восстанавливается повтором без второй команды.
- Неверный webhook secret не достигает базы.
- Миграции и seed повторяемы; checksum защищает применённую историю.
- Реальный PostgreSQL, Worker-тесты, CLI-тесты, typecheck, сборка и независимое ревью.

Фактические результаты добавляются только после выполнения команд.
