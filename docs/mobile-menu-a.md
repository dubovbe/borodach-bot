# Мобильное меню A

Статус: утверждённый дизайн реализован, локальные проверки и независимое SPEC/QUALITY ревью пройдены. Полный CI, обновление тестового бота и ручная проверка на телефоне ещё выполняются. Основа — [дизайн](superpowers/specs/2026-11-09-mobile-menu-design.md) и [план](superpowers/plans/2026-11-09-mobile-menu.md).

## Что изменилось

Общая навигация больше не помещает пять или шесть пунктов в один ряд. Каждый пункт занимает отдельную широкую строку: «📋 Мои записи», «⚙️ Настройки», доступные рабочие пункты и, для администратора, «🛠 Управление». «Записи для переноса» сокращены до «🔄 Переносы». Такая же раскладка используется после отправки заявки.

В рабочем месте сверху остаётся короткая пара «📅 Сегодня» / «🗓 Неделя»; «📆 Выбрать день», «📥 Заявки», «✍️ Записать клиента» и «📊 Статистика» показаны отдельно. «⬅️ К рабочему месту» возвращает на прежний экран. Условия доступа, action/callback, версии и обработка повторов сохранены.

Текст reply-кнопок контакта, внутренние формы админского редактора, даты/время, услуги, стоимость, графики и правила записи не менялись. Telegram по-прежнему управляет размером шрифта и темой; код меняет подписи и раскладку.

## Проверка

До изменения исходников Worker-тесты показали старые ряды из двух/пяти/шести пунктов и прежний ряд рабочего места: 21 ожидаемый failure. После правки прошли 64 затронутых Worker-теста, 91 unit-тест, весь Worker-набор из 114 тестов, TypeScript и dry-run сборка. Основной агент отдельно повторил 64 затронутых теста. Два PostgreSQL-тестовых файла получили только новые точные подписи кнопок; полный SQL-набор проверяется в CI.

Независимый Code Reviewer проверил весь новый diff: SPEC PASS / QUALITY PASS. Тесты связывают отображённые UUID с сохранёнными действиями, проверяют роли до профиля, оба способа построения общей навигации и переходы рабочего места.

После обновления понадобится свежий `/start`: старые сообщения могут сохранять прежние кнопки. Реальную читаемость проверяем на телефоне с обычным и увеличенным текстом. До этого ручная приёмка этой правки остаётся открытой. Настройка резервных копий остаётся отложенной по решению пользователя.
