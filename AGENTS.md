- Пользователь согласовал 2026-11-06 стартовые настройки разработчика и проверяющего: model="gpt-6.1-sol", reasoning_effort="medium". При запуске этих работников указывать оба параметра явно и fork_turns="none", передавая только нужный контекст. Усиление для конкретной сложной задачи сначала обсудить с пользователем. - Для этапа 2 пользователь отдельно согласовал проверяющего GPT-6.1 Sol + High; разработчик остаётся Sol + Medium. Это исключение этапа, не изменение глобальных настроек. Пользователь сообщил, что поставил Sol High и в текущем чате; агент не менял настройку самостоятельно.

## Оркестрация и экономия

- Основной агент координирует работу и отвечает за целостность результата.
- По мере необходимости делегировать небольшие задачи с конкретным результатом и проверкой. Не запускать постоянно работающую команду и не делегировать ради самого делегирования.
- Передавать работнику только нужную спецификацию, файлы и критерии готовности. По возможности использовать изолированный контекст, не копировать всю переписку.
- Не создавать вложенные команды без конкретной необходимости. Не опрашивать агентов частыми короткими вызовами.
- Проверка субагента не заменяет собственную проверку изменений основным агентом.
- По явной просьбе пользователя 2026-11-06 установлен полный Agency Agents из подтверждённого источника https://github.com/msitarzewski/agency-agents: 283 роли. Версия и результаты проверки — docs/agency-agents-installation.md. Команда и ограничения — docs/agent-team.md: основной агент как оркестратор, Backend Architect для ограниченных задач, Code Reviewer для независимого ревью; специалисты по необходимости. На этапах1–3 spawn_agent не имел agent_type: роль явно читалась из TOML. На этапе4 обновлённый инструмент принял agent_type Backend Architect и Code Reviewer; теперь роль выбирается нативно в этом чате, без переустановки файлов. Не запускать весь каталог и не менять глобальные настройки/модели автоматически. Superpowers доступен.

## Git и данные

- Делать отдельный осмысленный коммит на завершённый этап. Не коммитить несвязанные изменения.
- Отправлять завершённые этапы в согласованный репозиторий GitHub. Не считать локальный коммит опубликованным без проверки удалённого результата.
- Пользователь выбрал публичный репозиторий для портфолио 2026-11-06: https://github.com/dubovbe/borodach-bot, origin/main. Отправка исходных двух коммитов проверена совпадением SHA локальной и удалённой main.
- Не включать токены, пароли, .env, локальные секреты Wrangler, рабочие базы и резервные копии в Git.
- Откат кода не равен откату базы. Изменения схемы сопровождать порядком восстановления.
- До заявления о готовности выполнить проверки, соответствующие изменению, и сообщить фактический результат. Для документации достаточно проверки diff и ссылок; приложение не тестировать, пока его нет.
